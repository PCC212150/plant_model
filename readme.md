# plant_model —— 甘蔗幼苗株高

从**俯拍平铺图**预测甘蔗幼苗的株高。用「三通道分割 + 几何量测」而不是端到端回归：
模型输出 `茎 / 地上部 / 种茎` 三张掩码，再由 [common/measure.py](common/measure.py)
算出株高。可解释、能出中间图查错、能复用旁边 [root_model](../root_model/readme.md) 的基础设施。

```
Deep_learning_model_for_sugarcane\
├── root_model\       根系模型（已完工，自带 git 仓库）
└── plant_model\      株高模型（本目录）
```

## 株高的口径（**全项目最重要的一条**）

> **株高 = 地上部沿「茎轴方向」的最大伸出量，从基部起算。**
> 茎轴 = `rsml 1.1`（幼苗与种茎之间的基点 → 可见的叶鞘开口顶端）；
> 基部 = 茎的两端里离种茎更近的那端。

**为什么这么绕，不直接量外接框：** 植株是**平铺**拍的，站起来的高度 = 躺着时沿茎轴伸出多远。
把植株放平时会绕茎轴滚一个角度，叶片在**垂直于茎轴**方向的分量会被压掉，但
**沿茎轴方向的分量是刚体旋转不变量** —— 滚多少都不影响它。

实测（8 张）：茎翘 **31.4°** 时，外接框的 x 跨度是 1769 px，沿茎轴只有 1444 px —— **偏大 22.5%**。

代价：平放时叶片折返/堆叠会改变"最远点"落在哪，所以**摆放方式仍然影响结果**。
这是采集端的事，算法只能筛查（见下面的「时点变化」），修不了。

## 标注要求

| 来源 | 含义 | 注意 |
| --- | --- | --- |
| json `above_ground` | 地上部范围 | **必须画成「沿茎轴方向的旋转矩形」**（labelme 的 4 点矩形），不要轴对齐 |
| json `stem` | **种茎的横截面**（polygon） | 不是新长出的茎！用来判定基部在哪一端 |
| rsml `1.1` | 茎：基部 → 叶鞘开口顶端 | 给出**茎轴方向** |
| rsml `1.1.x` | 各叶片折线 | 本轮模型不用（`tool/measure_plant` 用它做筛查） |

### 为什么 `above_ground` 必须沿茎轴画

轴对齐矩形的"沿茎轴最远点"落在**角**上，而角上没有植株，于是株高系统性偏大：

| 植株 | 茎倾角 | 折线算的株高 | 轴对齐框量 | **旋转框量** | 轴对齐偏差 | **旋转框偏差** |
| --- | --- | --- | --- | --- | --- | --- |
| C001-1_1229 | −1.0° | 2563 | 2573 | 2565 | +0.4% | +0.1% |
| C001-1_1231 | 10.2° | 2492 | 2604 | 2495 | +4.5% | +0.1% |
| C001-2_1229 | 15.4° | 2706 | 3186 | 2711 | **+17.7%** | +0.2% |
| C001-2_1231 | 31.4° | 1444 | 1695 | 1446 | **+17.3%** | +0.1% |
| 其余 4 张 | | | | | +0.2~4.3% | ≤+0.3% |

旋转矩形把偏差从**最多 +17.7% 压到 ≤0.3%**（数学上：对齐后矩形沿轴的长度 ≡ 植株沿轴的长度）。
标注成本几乎不变 —— 还是 4 个点，只是摆正方向。

> 代码两种都认（4 点按原样保留、2 点展开成 4 角），但**用 2 点会打印告警**。

## 敏感度（决定模型该练到什么程度）

| 扰动 | 对株高的影响 |
| --- | --- |
| 地上部掩码边界 ±2 / 4 / 8 / 16 px | ∓2 / 4 / 8 / 16 px（≈ **0.1%/px**） |
| 茎轴方向偏 1° / 2° / 5° / 10° | ±0.6% / 1.2% / **2.2%** / 4.7% |

**边界可以糙，方向不能糙。** 掩码边界差 16 px 才 0.65%，但茎轴差 5° 就是 2.2% ——
所以 **`shoot` 通道的精度决定成败**。

而 `shoot` 恰恰是三个通道里最小的，**而且它有多细取决于输入分辨率**（实测）：

| `--size` | 缩放 | 线宽 | shoot 面积 | sett | above |
| --- | --- | --- | --- | --- | --- |
| 512 | 0.09 | **1 px** | 0.053% | 0.14% | 19.5% |
| 768 | 0.14 | **1 px** | 0.035% | 0.15% | 19.3% |
| 1024 | 0.19 | 2 px | 0.027% | 0.14% | 19.3% |
| 1536 | 0.28 | 3 px | 0.036% | 0.14% | 19.3% |
| 2048 | 0.37 | 4 px | 0.040% | 0.14% | 19.2% |

**512 下 `shoot` 只有 1 px 宽 —— 那是学不动的**（本机冒烟就是 512：shoot Dice 0.024）。
正式训练**至少 1024，建议 1536**。若 shoot Dice 仍然卡住，按顺序试：
① 再加分辨率 ② 调大 `LOSS_POS_WEIGHT`（10 是照搬 root_model 的经验值、大概率偏低）
③ 加粗 `MASK_LINE_WIDTH`（改这两项都要重训，且 train/test 必须同值）。
