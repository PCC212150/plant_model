# 量株高 + 筛查摆歪的植株

读 labelme json + RSML 标注，算出**株高**和**基点到叶尖的长度**，并把「拍的时候没摆正」的植株挑出来。

## 标注口径（2026-09-18 与用户确认）

| 来源 | 含义 |
| --- | --- |
| json `above_ground` 矩形 | 地上部的外接框 |
| json `stem` polygon | 种茎的横截面（不是新茎） |
| rsml `1.1` | 幼苗与种茎之间的**基点** → 可见的**叶鞘开口顶端**，即**茎**，也就是**茎轴 = 植株的自然竖直方向** |
| rsml `1.1.1`、`1.1.2`… | 各叶片折线，起点都接在 `1.1` 的末端 |

**基点到叶尖长度 = `|1.1| + |1.1.x|`** —— 先走茎到叶鞘顶端，再沿这条叶走到叶尖。

## 株高怎么算（全工具最关键的一步）

植株是**平铺**拍的，所以"站起来的高度"= 躺着时**沿茎轴方向**伸出多远。工具有两列：

| 列 | 算法 | 说明 |
| --- | --- | --- |
| **株高(投影)** | 地上部**所有点**在茎轴方向上的最大伸出量 | **推荐口径** |
| 株高(x跨度) | `above_ground` 矩形的 x 跨度 | 用户原口径，茎水平时才等于上面那个 |

**为什么投影比 x 跨度好**：平放时植株会绕茎轴滚一个角度，叶片在**垂直于茎轴**方向的分量会被压掉，
但**沿茎轴方向的分量是刚体旋转不变量** —— 滚多少都不影响它。而 x 跨度里混进了**茎本身倾斜**的分量。

实测这批数据：

| 植株 | 茎倾角 | x 跨度 | 茎轴投影 | 偏差 |
| --- | --- | --- | --- | --- |
| C001-1_1229 | −1.0° | 2606 | 2563 | +1.7% |
| C001-2_1229 | 15.4° | 3044 | 2706 | **+12.5%** |
| C001-2_1231 | 31.4° | 1769 | 1444 | **+22.5%** |
| C001-3_1231 | −19.9° | 2125 | 2286 | **−7.1%** |

茎接近水平时（±10° 内）两者差 2% 以内；**一旦翘起来就错得厉害**。

## 为什么要筛查

**摆放角度确实在变**（用户 2026-09-18 看图确认）。叶片被压平的过程中会折返、堆叠，
"最远的那一点"落在哪会跟着摆法变，于是同一株不同时点的数就不可比。

> 实例：`plant_C001-2_20241231CK` 的茎轴投影只有 1444，而同一株两天前是 2706
> —— 植株不会两天缩 47%。

两个判据（互相独立）：

| # | 判据 | 阈值 | 抓什么 |
| --- | --- | --- | --- |
| ① | **叶尖投影比** = 最远那条叶的**叶尖**的投影 ÷ 地上部最大投影 | < 0.80 | 远小于 1 说明最远点是**叶身中段**（叶折返/堆叠），不是叶尖 |
| ② | **时点变化** = 同一植株相邻时点的株高(投影)变化 | 下降 > 10% | 植株是长的，株高不该明显下降 |

判据②按 `plant_key` 归组（`plant_C001-1_20241229CK` → `C001-1`），需要同一株有多个时点。

## 用法

```
python measure_plant.py --dir "..\datasets\plant" --dry-run           # 只看筛查报告
python measure_plant.py --dir "..\datasets\plant"                     # 出 CSV
python measure_plant.py --dir "..\datasets\plant" --mm-per-px 0.19    # 顺带出 mm 列
python measure_plant.py --dir "..\datasets\plant" --drop-tol 0.15     # 放宽判据②
```

| 参数 | 说明 |
| --- | --- |
| `--dir` | 含 jpg + json + rsml 的文件夹（**必填**） |
| `--out` | CSV 路径，默认 `<dir>\plant_measure.csv` |
| `--mm-per-px` | 像素→毫米；0（默认）只输出像素。**刻度板一格 26 px**，一格多少毫米填进来即可 |
| `--drop-tol` | 判据②的下降容忍，默认 0.10 |
| `--dry-run` | 只打印报告，不写 CSV |

输出 CSV 是 UTF-8 BOM（Excel 直接开），表头前若干行 `#` 注释写清口径、换算和判定规则。

> ⚠️ **CSV 默认写在数据文件夹里**。如果这个文件夹接下来要拿去划数据集
> （`separate_dataset` 是按「文件夹里所有文件」分组的），记得先把 CSV 挪走。

## 一个写解析器时踩过的坑（别重犯）

RSML 的 `<root>` 是**嵌套**的 —— `1.1.1` 整个写在 `1.1` **内部**。
如果用正则 `<root[^>]*>(.*?)</root>` 去抓，非贪婪会匹配到**第一个** `</root>`（那是子根的闭合标签），
于是父根把子根的点全算进自己的长度里：**实测把 963 px 的茎算成了 2809 px**。

本工具用 `xml.etree.ElementTree` 解析，收集某个根的点时**显式跳过 `tag == "root"` 的子元素**
（与 [root_model/common/rsml_parse.py](../../../root_model/common/rsml_parse.py) 语义一致）。
写完做过逐根比对：8 个文件、每个文件的每个根，两边点数与坐标**完全相等**。

## 还要做的事

- **采集端定规程**：拍之前把叶片捋向种苗对侧、沿茎轴铺平。这比任何算法都管用 ——
  摆放角度一变，同一株的数就不可比，这是模型修不了的。
- **刻度板一格多少毫米**：给了就能输出 mm。
- **预测侧也要跑同一套筛查**：模型输出 `above_ground` 之后，同样算株高 + 判据①②，
  线上采集时就能自动把摆歪的图挑出来重拍。
